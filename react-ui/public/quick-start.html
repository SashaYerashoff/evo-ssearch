Operator Quick Start

Connect Luxriot Evo, select streams, create attention probes and VLM alerts, review summaries, and ask the agent for evidence.

Start here. Open http://<EVA-IP>:5000, sign in with the credentials supplied by the administrator, then configure Luxriot before starting any stream. The interface can be switched between English and Latvian in Appearance; evidence, channel names, summaries, reports, and agent conversations are not translated.

1. First connection to Luxriot Evo

  1. Open the side MENU, then Settings → Luxriot.
  2. Set Base URL to the Evo HTTP API address, for example http://192.168.1.50:8080. Enter the Evo Username and Password. Set a valid Default channel ID.
  3. Press Save settings. A blank password means “keep the current password”, not “remove it”.
  4. Wait for the bottom status line to show LUXRIOT CONNECTED and a non-zero channel count. A green state means EVA received fresh inventory or stream data, not merely that an address is configured.
  5. If channels do not appear, confirm that EVA can reach the Evo IP, the API port is correct, and the Evo account can view the required cameras. Re-open Settings and save corrected credentials.
Do not start all cameras at once. Select the intended 6–8 operational channels and bring them up in small groups while watching latency and GPU load. PTZ movement or a preset tour changes the scene; EVA marks that view transition and needs a short steady interval to establish the new view.

2. The main interface

3. Start and review stream summaries

  1. Open Stream summaries → Stream settings. Select a channel. Channel selection here is independent of Stream review.
  2. Choose the batch limit, sampling cadence, and model. The appliance is designed to adapt the actual frame selection using motion and attention signals; do not use a high fixed rate merely to compensate for a weak alert definition.
  3. Press Apply changes, then Start summaries. Use Flush only when an incomplete batch must be submitted immediately.
  4. Return to Stream review. Select the channel, period, and resolution: observations (L0), 15-minute (L1), one-hour (L2), or eight-hour (L3). Auto chooses a useful depth for the selected period.

How to read a summary

  • L0 describes one visual batch and carries the direct alert decision.
  • L1/L2/L3 consolidate shorter descriptions into minutes, hours, and an eight-hour operator-oriented account. They are not independent visual observations.
  • Alert badges show severity and count. Burst means motion exceeded the channel baseline. PTZ/view badges mean the camera moved or the current view has not yet been confirmed.
  • The representative image is the VLM cover frame. Click it to open archive review with neighbouring batch frames. Recorder playback may take tens of seconds to prepare.
  • BATCH_STATE_JSON is machine state. Operators normally read the narrative above it; expand the JSON only for diagnostics.

4. Create a semantic probe

  1. Open Probes and press New probe.
  2. Choose the channel and give the probe an operational name, such as “small craft entering harbour gate”.
  3. In Positive scene, describe what should attract attention. In Negative look-alike, describe the closest normal scene that should be suppressed. Example: positive small sailing craft crossing the harbour entrance; negative open water and breakwater with no nearby craft.
  4. Keep the displayed SigLIP defaults for Positive floor and Margin on the first run. Change thresholds only after reviewing real hits and misses.
  5. Optionally enable Make bookmarks in Luxriot on hits, choose severity, cooldown, and deduplication. Enable the probe and press Save probe.
  6. Watch several genuine and quiet examples. Raise the positive floor to reduce broad matches; increase the margin when the negative look-alike scores too close. Use ROI only for a fixed camera view—do not copy an ROI blindly across PTZ presets.
A probe is an attention hint, not a fact. A hit narrows the search and may raise frame density. Confirm safety/security conclusions in the visual evidence or VLM description.

5. Create a VLM alert

  1. Open Stream summaries → Stream settings, select the channel, then press Prompts & alerts.
  2. Open the Alerts tab. Describe observable alert criteria, severity, and important exclusions. Keep identity claims conservative and use visible behaviour, geometry, and direction of travel.
  3. Example: HIGH: two vessels are converging on crossing trajectories near the harbour entrance, or a small craft is on a collision course with a larger vessel. Do not alert on perspective-only overlap when motion history shows safe separation.
  4. Enable Make bookmarks on alerts if the event must appear in Evo. Set a cooldown appropriate to the event duration, then press Save.
  5. Run the stream and verify the alert badge, cover frame, neighbouring frames, and bookmark time. Correct the criterion when evidence is ambiguous; do not compensate only by lowering thresholds.
Stream vs Alerts. The Stream prompt explains how to interpret the scene. Alert/watch criteria belong in Alerts, so they do not compete with the core L0 observation contract.

6. Search evidence and report an incident

  • In Archive, select one or more valid channels, evidence sources, and a time range. Use Text query for semantic search; its similarity control filters the returned result set from 0 to 1.
  • Click a result to inspect adjacent frames. Use Play archive video to request recorder footage around the evidence timestamp.
  • Report incident creates a durable incident draft from an evidence point. Review the proposed start/end, evidence sequence, and description before saving.
  • Use Report false positive when an alert is visually wrong. This feedback is retained for later consolidation and probe/alert tuning.

7. Ask the EVA Agent

Good requests contain a channel or group, an explicit time window, and the required evidence/output.

  • Show high and critical VLM alerts on Harbour Gate West during the last two hours. Include evidence timestamps.
  • Search the last three days for small sailing craft entering the harbour. Group likely repeats and show the six strongest visual matches.
  • Build an incident report around this alert, including the first approach, closest point, and final separation.
  • Check stream health for the selected eight channels and list coverage gaps without guessing what happened during missing video.
  • Operator ON allows the agent to drive supported UI views and prepare controlled actions. Operator OFF keeps the conversation/read path but blocks UI control.
  • Research traces remain collapsed until the operator opens them. Tool activity is evidence of a lookup, not proof that the final wording is correct.
  • Ask the agent to distinguish observed evidence, inference, and coverage gaps. Challenge claims of “nothing happened” when coverage is incomplete.
  • The guided protocol: deploy workflow is not part of this handoff. Configure the initial channels, prompts, and probes manually using the steps above.

8. Handoff health check

  1. Luxriot status becomes connected only after fresh data arrives.
  2. The intended channels appear and the selected stream produces a recent preview.
  3. A test stream produces an L0 summary within its configured maximum batch window.
  4. A test probe shows current frames and can be enabled/disabled.
  5. Archive search returns a real thumbnail; recorder playback opens around that evidence time.
  6. The agent can answer a bounded stream-status request without inventing unavailable coverage.

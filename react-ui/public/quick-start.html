Operator quick start

Connect Luxriot Evo, start channel descriptions, create probes and VLM alerts, review evidence, and work with EVA Agent.

EnglishქართულიLatviešu
Start here. Open http://<EVA-IP>:5000 and sign in with the account supplied by the administrator. Connect Luxriot Evo before starting channel analysis. The interface language can be changed under Appearance; camera names, evidence, model descriptions, and conversations are not translated automatically.

1. Connect Luxriot Evo

  1. Open MENU, then Settings → Luxriot.
  2. Enter the Evo HTTP API address in Base URL, for example http://192.168.1.50:8080, followed by the Evo username and password.
  3. Press Save settings. A blank password field means “keep the existing password”; it does not erase it.
  4. Wait for LUXRIOT CONNECTED and a non-zero channel count in the bottom status bar. Green means EVA received fresh data, not merely that an address was saved.
  5. If channels are missing, check the IP address, API port, network access, and the Evo user's permission to view those cameras.
Do not start every channel at once. Start the intended channels in small groups while watching description delay and GPU load. A PTZ move or tour preset changes the view; EVA needs a short stable interval to confirm the new scene.

2. Main areas

3. Start channel descriptions

  1. Open Stream summaries → Stream settings and select a channel.
  2. Keep the recommended batch and cadence initially. EVA may increase frame density when motion or attention signals rise.
  3. Press Apply changes, then Start summaries. Use Flush only when an incomplete batch must be sent immediately.
  4. In Stream review, select the channel, time range, and level: L0 observations, L1 15 minutes, L2 one hour, or L3 eight hours. Auto selects a suitable depth.
How to read a description. L0 is one visual batch and its direct VLM alert decision. L1–L3 consolidate lower levels; they are not independent visual observations. Burst means motion above that channel's measured norm. Open the representative image to inspect submitted frames. BATCH_STATE_JSON is machine-readable state and normally does not need operator review.

4. Create a semantic probe

  1. Open Probes and press New probe.
  2. Select a channel and use an operational name, such as “small vessel at harbour gate”.
  3. In Positive scene, describe the visible situation to find. In Negative look-alike, describe the closest normal view to suppress. Example: small sailing craft crossing the harbour entrance versus open water and breakwater with no nearby craft.
  4. Initially keep the proposed Positive floor and Margin. Change thresholds only after reviewing real hits and misses.
  5. If needed, enable Luxriot bookmarks and set severity, cooldown, and deduplication before saving.
  6. Use an ROI only for a fixed camera view. Do not reuse one ROI blindly across different PTZ presets.
A probe hit is not a fact. It narrows attention and may increase frame density. Confirm safety-relevant conclusions in visual evidence or a VLM description.

5. Create a VLM alert

  1. Open Stream summaries → Stream settings, choose a channel, and press Prompts & alerts.
  2. Under Alerts, state visible criteria, importance, and relevant exceptions. Describe observable action, geometry, and direction; do not invent identity or intent.
  3. Example: HIGH: two vessels are converging on crossing trajectories near the harbour entrance. Do not alert on perspective-only overlap when motion history shows safe separation.
  4. Enable bookmarks if the event must appear in Evo, and choose a cooldown that matches the event duration.
  5. Verify the alert badge, representative frame, neighbouring frames, and bookmark time. Fix ambiguous criteria in the text instead of only lowering a threshold.
Stream and Alerts have different jobs. Stream prompts explain how to interpret the scene. Monitoring and alarm criteria belong under Alerts.

6. Search the archive and report an incident

  • In Archive, select channels, evidence sources, and a time range. Text query performs semantic search.
  • Open a result to inspect neighbouring frames. Play archive video requests Evo footage around the evidence time and may take several tens of seconds to prepare.
  • Report incident prepares an incident with start, end, ordered evidence, and description. The operator must verify it before saving.
  • Use Report false positive for a visually incorrect alert. Feedback is retained for later probe and alert tuning.

7. Work with EVA Agent

A good request names the channel or group, an exact time range, and the required evidence or output form.

  • Show high and critical VLM alerts on Harbour Gate West during the last two hours. Include evidence timestamps.
  • Search the last three days for small sailing craft entering the harbour. Show the six strongest visual matches.
  • Build an incident report around this alert, including the first approach, closest point, and final separation.
  • Check stream health for the selected eight channels and list coverage gaps without guessing what happened during missing video.
Operator ON lets the agent navigate supported views; Operator OFF blocks it. Ask the agent to separate observed evidence, inference, and coverage gaps. A tool call proves that a search ran, not that every statement in the final text is true.

8. Pre-shift check

  1. Luxriot becomes green only after fresh data is received.
  2. The expected channels are visible and the selected channel has a current preview.
  3. A test channel creates an L0 description within the configured maximum batch window.
  4. A test probe shows current frames and can be enabled and disabled.
  5. Archive search returns a real image; Evo playback opens video around the correct time.
  6. The agent can check channel health without inventing events during missing coverage.
